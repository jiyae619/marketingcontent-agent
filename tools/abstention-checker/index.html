Why this tool exists

A rubric contains two kinds of criteria, and they behave completely differently.

Intrinsic criteria are judgable from the artifact alone. Is the grammar clean? Is the tone robotic? Is there a slur in it? The text in front of the judge is the whole evidence base.

Relative criteria are defined against something else. "Accurate" means accurate to a source. "Complete" means complete relative to a request. "On-brief" means on which brief. If that referent isn't in the judge's context, the criterion isn't hard to judge — it's impossible to judge.

And the judge will score it anyway. That's the part that costs you. In the system this tool was extracted from, a small local model was asked to grade grounding with the source brief set to None. It returned confidence: "medium" and overall: 80 — a confident number for a property it had no way to observe. It didn't hedge, and nothing downstream could tell that verdict apart from a real one.

The fix isn't a better prompt. Asking the model to notice its own blindness is asking the blind spot to report itself. Whether the referent was supplied is a fact the calling code already knows — so the calling code should enforce abstention, deterministically, before the score is ever trusted. That guard is what this tool writes for you.

One more consequence people miss: a contaminated criterion doesn't just invalidate itself. If you average criteria into an overall score, or gate a safety decision on a family of them, one unverifiable criterion silently contaminates the aggregate — which is usually the number someone actually ships on.
